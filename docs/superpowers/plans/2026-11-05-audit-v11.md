# 审计 v1.1 实施计划（P3）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 在不改变 v1.0 条目哈希的前提下交付审计 v1.1：`payload_digest`、事件导出复算、DDL 对齐、append-only、临时命令全覆盖与可选定时锚定。

**Architecture:** 纯语义放 `core/audit`（`AuditEntry.payloadDigest`、`AuditPayloadDigest`、`AuditVerifier` 事件导出入口）；命令运行时通过 `TemporalCommandAudit` seam 在事务内写审计；PostgreSQL 用迁移 V2 对齐表结构并加 append-only 规则；定时锚定默认关闭，开启时由 `@Scheduled` 调用 `AuditChain.anchorNow()`。

**Tech Stack:** Java 21、Maven 多模块、JUnit 5、AssertJ、Jackson 3、Spring `JdbcTemplate`、Testcontainers（`postgres:17-alpine`）。

**Spec:** `docs/superpowers/specs/2026-11-05-contract-conformance-design.md` §7.6 / §9 P3；规范 `05-audit-contract/hash-chain.spec.md` v1.1、`audit.ddl`、`tests/audit-contract.test.yaml`。

## Global Constraints

- 产品代码不得出现规范名（不区分大小写），唯一例外：`EIS-{3位}-{3位}`、Schema URI `eis://…`、DDL 域类型 `eis_id` / `eis_version` / `eis_timestamp`。
- `core` 零 Spring、零 seedj 模块依赖；不新增 Maven module。
- v1.0 条目哈希逐字节不变：`payload_digest` 为 `null` 时不追加第 11 行。
- 摘要投影固定为 `[{id,type,payload}...]`，按审计条目 `payload.event_ids` 顺序；空投影为 `4f53cda18c2baa0c0354bb5f9a3ecbe5ed12ab4d8e11ba873c2f11161202b945`。
- 所有时间 UTC 微秒；标识 UUIDv7；审计写入与命令同事务。
- 每个任务结束运行该模块 `mvn -o -B -pl <module> -am test`；提交信息 `feat:` / `test:` / `fix:` / `docs:`。
- 审计表 append-only：`UPDATE` / `DELETE` 必须被数据库规则拦截。

## Review Focus

- **v1.0 兼容**：未带 digest 的旧条目规范化必须仍是 10 行，创世哈希 `447c6e…7410` 逐位不变。
- **事件顺序**：`payload.event_ids` 顺序与事件导出顺序不一致时，摘要必须按 `event_ids` 重排后复算，不能按导出顺序。
- **缺事件**：事件导出缺少被引用事件时必须是 `payload_digest_missing_event`，不得降级为“通过”。
- **事务边界**：临时命令审计必须在对象行/命令终态同一事务内；审计失败必须回滚业务写入。
- **append-only**：规则存在时 `UPDATE` / `DELETE` 返回 0 行且数据不变；不能只在应用层拦截。
- **锚定默认关闭**：未显式开启时不得注册定时任务；开启后锚定失败不得静默吞掉（记日志并保留链）。
