## 3. 数据与时点

- `iam_binding` / `iam_proxy` 采用双时间轴列：`valid_from` / `valid_to`（业务，半开）、
  `recorded_at` / `superseded_at`（系统）；
- 存储层 SQL 过滤业务区间与 `recorded_as_of`，内存实现使用同一 `effectiveAt` 语义；
- 绑定作用域为 `JSONB`，SoD 按 `department` / `organization` / `warehouse` 比较；
- 属性快照选 `asOf <= 请求 as_of` 的最新一条，`expires_at` 决定 fresh/stale。

## 4. 偏差与裁定

| 项 | 裁定 | 影响 |
|---|---|---|
| 绑定/代理标识沿用字符串 | 既有 IAM 用户/角色 ID 是字符串；绑定必须直接引用 `iam_role` | 与冻结 Schema 的 uuid format 存在文档级差异 |
| 角色定义无独立双时间轴 | 角色含义变更不做历史重建；时点语义由绑定/代理承担 | 规范 `role.schema.json` 的 `valid_from/recorded_at` 未落到角色表 |
| 属性源可插拔 | 默认 `InMemoryIamAttributeSource`；生产由 HR 属主实现 `IamAttributeSource` | P4 只证明 fail-closed 语义，不内置 HR 数据 |
| 条件来源 | `IamPermissionCondition` bean；P4 不实现 manifest 解析 | manifest 加载留给 P6 活样板 |
| `/check` 请求的 `attributes` | 支持调用方已拉取快照；缺省走服务端属性源 | 与契约可选字段一致 |
| 属性端点鉴权 | `CallerProvider` + `hr.attributes.read` / `iam.attributes.read` | 未额外增加 BFF 隔离测试；由应用统一认证链兜底 |
