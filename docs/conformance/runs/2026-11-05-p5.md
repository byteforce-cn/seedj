## 2. 兼容性门禁

- 工件：`docs/conformance/schema/` 与 `docs/conformance/baseline/` 各 9 个 Schema；
  `docs/conformance/api/` 含 command/query/event/resolution/attributes 契约副本；
- 规则：`config/conformance/compatibility.rules.yaml`（规范冻结副本）；
- 入口：根 POM `-Pconformance` → `config/conformance/check-compatibility.sh`；
- 负例自检 `gate-selftest.sh`：
  - 字段删除 → `--fail-on MAJOR` 退出码 1；
  - 可选字段新增 → 退出码 0；
- 工具缺席：脚本显式 `exit 1`，Maven profile `failonerror` 阻断，不静默跳过。

## 3. 迁移与回滚

| 能力 | 证明 |
|---|---|
| 回滚删除对象并清理历史 | `JdbcMigrationRollbackTest.rollbackDropsObjectsAndRemovesHistory` |
| 回滚脚本失败整体事务回滚 | `rollbackIsTransactionalOnScriptFailure` |
| 缺少回滚脚本显式失败 | `rollbackWithoutScriptFailsExplicitly` |
| 回滚后可重新 migrate | `rollbackDropsObjectsAndRemovesHistory`（同一测试） |
| checksum 覆盖回滚脚本 | `MigrationChecksumsTest.checksumCoversRollback` |

`Migration` 新增可选 `rollback` 组件；3 参构造器保持兼容。`JdbcMigrationRunner.rollback`
在同一 advisory lock + 事务内逆序执行并删除历史行。

## 5. 偏差与裁定

| 项 | 裁定 | 影响 |
|---|---|---|
| 规范仓库路径 | 路径字面量只放在 `config/conformance/*.sh`；`pom.xml` 用空 `spec.root` 属性，脚本按仓库相对位置解析 | 满足产品代码命名门禁 |
| `compatibility-checker --self-test` | 本机缺少 `jsonschema` 时该工具的规则 Schema 负例会失败；门禁不依赖它，使用 `gate-selftest.sh` 证明真实 diff 判定 | 工具自测的环境依赖未改变；实际判定路径不降级 |
| 基线 | 首版 `baseline/` 与 `schema/` 相同；发布后只更新 `schema/` | 首次发布前无历史差异可判 |
| 回滚演练 | 以 Java 文本迁移 + Testcontainers 执行，不依赖外部 `migration-generator` | 与仓库“Java 侧可执行证明”一致 |
