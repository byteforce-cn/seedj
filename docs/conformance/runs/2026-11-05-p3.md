## 4. DDL 与 append-only

- 迁移 V2 将 `occurred_at` 重命名为 `timestamp`，新增 `payload_digest`；
- 长度 CHECK：`audit_hash_len` / `audit_prev_hash_len` / `audit_payload_digest_len`；
- 索引：`idx_audit_sequence` / `idx_audit_timestamp` / `idx_audit_actor` /
  `idx_audit_resource`；
- 规则：`audit_no_update` / `audit_no_delete`（`DO INSTEAD NOTHING`）；
- 证明：`JdbcAuditStoreTest.ddlHasColumnAndChecks`、
  `JdbcAuditStoreTest.updateAndDeleteAreBlockedByAppendOnlyRules`。

## 6. 偏差与裁定

| 项 | 裁定 | 影响 |
|---|---|---|
| `audit_entry.id` / `actor` / `resource_id` 保持 TEXT | 既有 `@Audited` 的 actor/resource 是业务字符串（`system`/`alice`/`e-1`）；强制 UUID 会破坏兼容。哈希只依赖稳定文本表示，v1.0/v1.1 向量不受影响 | 与冻结 DDL 的 UUID 类型声明存在文档级差异；功能与哈希语义一致 |
| 规范 3.2 称 digest 为“第 11 行” | v1.0 规范化实际为 9 行，digest 为第 10 行；`fb4cc462…` 向量证明实现正确 | 仅文档措辞差异 |
| 审计写入顺序 | 追加 → 事件 → 审计 → 命令终态。放在 `complete` 之前，审计失败时命令仍为 pending，`abandon` 可释放幂等键 | 审计看到的是内存中的 accepted 记录，未提交状态由事务保证 |
| 迁移脚本 | 用 `ALTER INDEX IF EXISTS` 替代 `DO $$` 块；`JdbcMigrationRunner` 按分号切分，不支持美元引号 | 语义等价 |
| 锚定首次延迟 | 新增 `initial-delay-millis` 供测试抑制 `@Scheduled` 首次立即执行 | 生产默认 0，行为不变 |
