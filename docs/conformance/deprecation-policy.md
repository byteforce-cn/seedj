# 弃用窗口政策

- 状态：生效
- 日期：2026-11-05
- 适用范围：数据契约（对象/事件/视图）、操作契约（HTTP/事件通道）、授权契约
- 判定权威：`config/conformance/compatibility.rules.yaml` 与规范
  `06-evolution-contract/compatibility.rules.yaml`

## 1. 基本原则

1. **先声明、后删除**：任何 `MAJOR` 变更必须先在兼容规则中定位条目，再按本政策走弃用窗口。
2. **窗口下限**：弃用公告必须持续 **≥2 个 MINOR 版本** 且 **≥90 天**，两者取较长者。
3. **可回滚**：删除/替换必须提供迁移脚本与回滚脚本；回滚演练见
   `docs/conformance/templates/` 与 `JdbcMigrationRunner.rollback`。
4. **可观测**：弃用期内旧字段/端点/事件继续可用；新代码不得写入旧字段时，必须双写或提供
   对账脚本。
5. **有 ADR**：每次 `MAJOR` 变更必须有 ADR，引用兼容规则条目、窗口起止与回滚方案。

## 2. 变更分级

| 级别 | 示例 | 动作 |
|---|---|---|
| PATCH | 文档、注释、无契约变化的内部重构 | 直接发布 |
| MINOR | 可选字段新增、可选参数新增、事件字段新增、枚举扩展 | 可直接发布；记录变更清单 |
| MAJOR | 字段/API/事件删除、类型变更、必填新增、枚举收缩 | 弃用窗口 + 迁移/回滚 + ADR |

## 3. 时间线

```text
MINOR N     发布弃用公告；旧能力保留；新能力可用
MINOR N+1   窗口继续；监控旧能力调用量；提供迁移指南
MINOR N+2   满足 90 天后，允许在下一个 MAJOR 删除
```

- 窗口起点以 **公告进入首个 MINOR 发布** 为准，不以分支合并日为准。
- 窗口结束前必须确认旧能力调用量为 0，或由 ADR 记录豁免与补偿措施。
- 紧急安全删除不受窗口限制，但必须有 ADR 与事后复盘。

## 4. 检查清单

- [ ] 兼容规则条目已定位（data / operation / event）
- [ ] 级别判定为 MAJOR，且 `requires` 列表逐项完成
- [ ] 弃用公告已进入至少 2 个 MINOR、且 ≥90 天
- [ ] 迁移脚本 + 回滚脚本已演练
- [ ] 双写/对账（如适用）已运行并记录差异率
- [ ] ADR 已链接本政策与兼容规则
- [ ] 变更清单已归档到 `docs/conformance/runs/`
