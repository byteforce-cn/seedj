# ADR-0003：1.0 的单租户边界

- 状态：已接受
- 日期：2026-11-07
- 决策者：Seedj 维护者

## 背景

`Caller.tenantId` 已经影响 IAM 的角色/绑定解析，但业务表没有 `tenant_id` 列；
如果继续暗示业务数据已隔离，会让调用方误以为跨租户读取会被拒绝。

## 决策

1.0 明确按 **单租户部署** 交付：

- `Caller.tenantId` 只用于 IAM（角色、绑定、属性、令牌）；不代表业务数据隔离。
- 业务对象 schema 不增加 `tenant_id` 元字段；生成 DDL 不添加租户列。
- 多租户作为后续大版本：需要 ADR、`tenant_id` 元字段、所有查询强制注入、PG RLS、
  迁移与跨租户负例，不在 1.0 的增量里悄悄加半套。
- 文档与错误信息不得宣称“已隔离”；需要多租户的部署方必须显式分库/分 schema。

## 后果

- 单租户部署的权限模型简单、可验证；
- 多租户客户需要等待后续版本，不能用“tenantId 已经存在”作为已隔离的证据；
- `Caller.tenantId` 的 IAM 语义保持不变，不破坏既有令牌与绑定。
